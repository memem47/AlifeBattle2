# AlifeBattle v0.4 Specification

## Goal

Introduce the first player-controllable battle commands.

The player can switch each team's movement behavior between:

- `ADVANCE`
- `HOLD`

This version establishes the basic command mechanism without introducing formations, units, command queues, or complex tactics.

## Initial State

At the start of a battle:

- Red command is `ADVANCE`.
- Blue command is `ADVANCE`.

This preserves the default behavior of v0.3.

## Commands

### ADVANCE

The team moves in its normal forward direction:

- Red moves right.
- Blue moves left.

Separation behavior remains active.

### HOLD

The team has no commanded forward movement.

Agents may still move slightly because of separation.

Agents do not move toward enemies while holding.

Local attack targeting remains active, so agents can still attack enemies that enter `ATTACK_RANGE`

## Player Input

Keyboard controls:

- `A`: toggle Red between `ADVANCE` and `HOLD`
- `B`: toggle Blue between `ADVANCE` and `HOLD`
- `R`: reset the battle

Each key press changes only the selected team's command.

## Command Visibility

The current command for each team should be visible on screen.

Example:

```text
Red: ADVANCE
Blue: HOLD
```

## Combat

The v0.3 combat model remains unchanged:

- attack targets are searched locally,
- only enemies within attack range can be targeted,
- movement does not depend on attack targets.

## Scope

v0.4 includes:

- persistent command state for each team,
- `ADVANCE`,
- `HOLD`,
- keyboard command switching,
- visible current command state.

## Out of Scope

- `RETREAT`,
- left/right maneuver commands,
- formations,
- multiple units,
- command duration,
- command queues,
- commander AI,
- morale,
- terrain.

## Done When

v0.4 is complete when:

- both teams start in ADVANCE,
- pressing `A` toggles the Red command,
- pressing `B` toggles the Blue command,
- `ADVANCE` produces forward movement,
- `HOLD` removes commanded forward movement,
- separation continues while holding,
- local combat continues while holding,
- current commands are visible,
- existing v0.3 behavior remains unchanged otherwise.
