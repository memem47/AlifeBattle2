# AlifeBattle v0.3 Design

## Design Goal

Replace enemy-driven movement with command-driven movement while keeping combat local and simple.

No general command framework is introduced yet.

## Movement

Each team has a fixed movement direction:

```text
Red  -> (1, 0)
Blue -> (-1, 0)
```

The movement vector is:

```text
command direction
    +
separation
    ↓
final movement
```

Agents no longer use an enemy position to calculate movement.

## Combat Targeting

Attack targeting happens independently from movement.

After movement is applied:

1. build a spatial grid from the current living-agent positions,
2. obtain nearby candidates from the current and neighboring cells,
3. keep only living enemies within ATTACK_RANGE,
4. select the nearest valid enemy,
5. resolve attacks using the existing cooldown and damage rules.

The spatial grid narrows the candidate set.
Exact distance checking remains required.

## Game Update

The intended update sequence becomes:
```text
update cooldowns
      ↓
snapshot positions
      ↓
build spatial grid
      ↓
calculate command movement
      ↓
calculate separation
      ↓
apply movement
      ↓
rebuild spatial grid
      ↓
select local attack targets
      ↓
collect attacks
      ↓
apply damage
      ↓
check battle result
```

The grid is rebuilt after movement because attack targeting must use the new positions.

## Responsibilities

```Game```

- owns the fixed team command directions,
- coordinates movement,
- builds spatial grids,
- selects local attack targets,
- resolves combat.

```Agent```

- stores individual state,
- calculates movement from a supplied direction,
- calculates separation,
- manages attack cooldown and damage.

```spatial_grid.py```

- groups agents by cell,
- returns nearby candidate agents.

## Deferred Design

v0.3 does not introduce:

- a Command class,
- a command queue,
- player command input,
- formations,
- unit hierarchy.

Those should be introduced only when a later version requires them.
