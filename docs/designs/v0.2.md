# AlifeBattle v0.2 Design

## Approach

v0.2 reuses the v0.1 architecture without introducing new simulation systems.

The initial implementation change only the army size and, if necessary, configuration values related to initial placement and visualization.

## Architecture

No architectural changes are planned.

The existing structure remains:

```text
main.py
 ├─ Game
 │   └─ Agent[]
 └─ renderer
```

## Scaling

`TEAM_SIZE` is increased from 10 to 50.

The existing nearest-enemy search and separation algorithms are retained initially.

No performance optimization is introduced until an actual performance problem is observed.

## Spatial Grid Optimization

A performance problem was observed when the simulation was stress-tested with much larger armies.

The separation calculation currently checks all living agents even though separation only depends on nearby agents.

v0.2 will therefore introduce a simple spatial grid for local-neighbor lookup.

The optimization will be introduced incrementally:

1. Define grid coordinates and visualize the grid.
2. Assign agents to grid cells.
3. Retrieve agents from the current and neighboring cells.
4. Use those nearby agents for separation calculation.
5. Measure performance again.

The initial cell size is equal to `SEPARATION_DISTANCE`.

With this cell size, any agent within separation distance must be located in the current cell or one of the eight neighboring cells.

The spatial grid will initially be used only for separation.

Nearest-enemy targeting remains a global search in v0.2.

## Performance Measurement

FPS is obtained from the Pygame clock in `main.py` and passed to the renderer.

Performance information is for observation only and is not part of the simulation state.

## Performance Benchmark

Performance is measured using a repeatable simulation benchmark.

The benchmark:

- uses a fixed random seed,
- processes a fixed amount of simulation time,
- uses a fixed delta time of 1/60 s,
- excludes rendering,
- and reports simulation updates per real second.

Multiple team sizes are measured to observe scaling behavior.

Performance measurements are not treated as automated pass/fail tests because results depend on the execution environment.

## Evaluation

After the 50-vs-50 version is implemented, evaluate:

- battle completion,
- simulation responsiveness,
- visual distinguishability,
- agent overlap,
- separation behavior,
- and any obvious performance bottlenecks

If a problem is found, identify its cause before changing the architecture.
