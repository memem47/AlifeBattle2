# AlifeBattle v0.1 Design

## Structure

```text
main.py
 ├─ Game
 │   └─ Agent[]
 └─ renderer
 ```

 File|Responsibility
 -|-
main.py|Main loop, input, delta time
game.py|Battle state and simulation update
agent.py|Individual agent state and behavior
renderer.py|Visualization
config.py|Parameters

## Initial Placement

Agents are placed randomly within each team's starting area. Randomness is used only for initial positions. All agents start with `attack_cooldown = 0`.

- Red agents start within a defined area on the left side.
- Blue agents start within a defined area on the right side.
- Initial positions vary for each battle.
- A fixed random seed may be used when reproducible behavior is needed for debugging or testing.
- Initial placement should avoid excessive overlap between agents.

## Agent

### State:

- id
- team
- position
- facing_direction
  
`facing_direction` stores the direction of the agent's most recent non-zero movement.
It is used for visualization and is updated from the final movement vector after target movement and separation are combined.
If an agent does not move during an update, its previous facing direction is preserved.

## Simulation Update

`Game.update()` orchestrates the simulation phases.

Detailed movement planning is delegated to private helper methods so that the main update sequence remains easy to follow.

Agent movement is calculated first and applied after all planned positions have been determined.

Game.update(dt):

```

update cooldowns
      ↓
select targets 
- Each living agent selects the nearest living enemy on every simulation update. 
- A previously selected target is not retained when another living enemy becomes nearer.
      ↓
calculate target movement
      ↓
calculate separation
      ↓
combine movement
      ↓
update facing direction
      ↓
apply movement
      ↓
collect attacks
      ↓
apply damage
      ↓
check battle result
```


Movement uses a position snapshot so results do not depend on update order.

Target movement and separation are calculated separately and then combined before positions are updated.

Separation pushes an agent slightly away from nearby agents to reduce excessive overlap. It is not intended to provide strict physical collision.

When the final movement vector is non-zero, the agent's `facing_direction` is updated to match that movement direction.

Attacks are collected before damage is applied so simultaneous combat does not depend on list order.

## Rendering

Rendering reads Game state but never modifies simulation state.

### Living Agents

Living agents are drawn as triangles.

The triangle is rotated so that its front points in the agent's `facing_direction`.

Agent color represents health using three levels based on the ratio:

```text
current HP / maximum HP
```

The health levels are:
Health ratio | Visual state
-|-
Above 2/3 | Healthy
Above 1/3 up to 2/3 | Damaged
1/3 or below | Critical

Each team uses its own color family so that Red and Blue agents remain distinguishable at every health level.

Exact colors are defined in config.py

### Dead Agents

Dead agents remain in the agents list and retain the position where they died.

They are not drawn as living triangles.

Instead, they are rendered using a simple circular death marker at their final position.

Dead markers do not move and do not participate in combat.

## Testing

Automated tests cover:

- movement,
- facing direction updates after movement,
- separation behavior,
- randomized initial placement constraints,
- reproducible placement with a fixed random seed,
- health-state classification,
- dead agents retain their final position,
- damage/death,
- attack range/cooldown,
- nearest-enemy selection,
- dead-target exclusion,
- win/draw detection,
- simultaneous attacks.

Manual tests

- Confirm that living agents are drawn as triangles.
- Confirm that triangles point in the direction of actual movement.
- Confirm that agent colors visibly change as HP decreases.
- Confirm that dead agents remain visible at their death positions as death markers.
